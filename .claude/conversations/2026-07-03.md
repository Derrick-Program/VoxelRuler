## Debug：1.17.1 macOS GLFW error 65548（已知缺陷 #3）
- 根因：`launch.rs` VersionDefault 的「Apple Silicon 原生模式」分支（required_java >= 16 → arm64 gamma + LWJGL 3.3.1 arm64）。原版 1.13–1.18 開機階段**無條件**呼叫 glfwSetWindowIcon（macOS guard 1.19 才加入），LWJGL 3.3.1 內建 GLFW 3.4 dev 回報 error 65548，此時 boot error callback（Window::bootCrash）仍生效 → TinyFD 對話框 + WindowInitFailed → 必炸。截圖對話框即 vanilla boot crash dialog，與驅動無關
- 修法：移除原生模式分支，1.13–1.18 預設 Java 一律 Rosetta x64 + LWJGL 3.2.3（GLFW 3.3.1 對 setIcon 靜默 no-op，MultiMC 標準解）；自訂 arm64 Java 路徑保留但啟動前 warn，崩潰後由 diagnose_graphics_crash 建議改「Follow Minecraft」
- 註解修正：mc_compat.rs header / LWJGL3_X64_OVERRIDE doc / 崩潰特徵表 / ADVICE 文字，影響範圍 1.13.x → 1.13–1.18
- 驗證：cargo check/clippy 乾淨，mc_compat 6 項 + classpath 替換測試通過；待實測 1.17.1 啟動

## Debug：1.16.4（Forge 35.1.37）GLFW 65544 on macOS 26 Tahoe
- 排查過程：override 選表 ✓、classpath 排除 ✓、3.2.3 jar sha1 ✓；natives 目錄的 libglfw.dylib 與 3.2.3 jar 內完全同 hash → 替換有生效，**是 3.2.3 本身不行**
- 根因（x64 C probe 於 macOS 26.5.1 實測）：LWJGL 3.2.3 內建 GLFW 為 2019-09 的 3.4.0-dev snapshot（早於 monitor 列舉重构），glfwInit 期間對每個螢幕發 65544「Failed to find service port for display」→ MC 開機 error callback 視為致命
- 兩難實測：LWJGL 3.3.0/3.3.1/3.3.3 x64 的 GLFW 在 Tahoe init 乾淨，但 setIcon 發 65548；1.16.4 client jar bytecode（djz/dez）證實開機期**無條件** setIcon、無 OS guard（昨天「guard 1.19 才加入」的判斷正確）
- 解法（= Prism/ManyMC osx-arm64 方案，跨架構化）：MinecraftMachina `3.3.1-mmachina.1` 的 **lwjgl-glfw bindings jar**——javap diff 證實 `nglfwSetWindowIcon` 移除了 `JNI.invokePPV`（Java 層 no-op、與架構無關）→ 兩張 LWJGL3 表都升 3.3.1 並共用 `MMACHINA_GLFW_BINDINGS`：
  - `LWJGL3_X64_OVERRIDE` → "lwjgl3-3.3.1-x64"：base + x64 natives 全 Mojang CDN（sha1 取自官方 1.19.2 JSON），glfw bindings 用 patched
  - `LWJGL3_OVERRIDE`（arm64）：glfw bindings 換 patched（順帶解掉自訂 arm64 Java 的 65548 必炸，launch.rs 相應 warn 已移除）
- 舊 natives 殘檔無害：未設 `org.lwjgl.librarypath`，LWJGL 從 classpath 解壓優先（17:47 覆寫行為即證據）
- 驗證：cargo clippy 乾淨、151 項測試全過；**待使用者實測 1.16.4 與 1.17.1**（1.17.1 之前也是 3.2.3 路徑，同樣受 Tahoe 影響）
- 供應鏈：MinecraftMachina GitHub 本已是 LWJGL2 表的既有來源；新 jar 以 sha1 釘住（e9a101bc…）
