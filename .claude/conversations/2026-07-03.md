#### 1. 版本下拉選單底部空白修正
- **問題**：選中末尾版本（如 1.0）時，`scroll-y` 計算導致 PopupWindow 底部出現多餘空白
- **修正**：開啟 PopupWindow 前的 `scroll-y` 計算改用 `max()` 夾緊上限

  - 否則取 `(idx-1)*32px` 與最大可捲量 `(total - 160px)` 的**較小值**，確保不超卷

#### 2. Mod Loader 選項不可用時禁用
- **問題**：即使某 Mod Loader 不支援目前選擇的 MC 版本，單選鈕仍可點選
- **修正**：`global.slint` 中 `fabric-available`、`forge-available`、`neoforge-available` 已有（Rust 端已設），UI 側補上：
  - `opacity: X-available ? 1.0 : 0.35`（視覺灰化）
  - `TouchArea { enabled: X-available; ... }`（阻止點選）

## Debug：1.17.1 macOS GLFW error 65548（已知缺陷 #3）
- 根因：`launch.rs` VersionDefault 的「Apple Silicon 原生模式」分支（required_java >= 16 → arm64 gamma + LWJGL 3.3.1 arm64）。原版 1.13–1.18 開機階段**無條件**呼叫 glfwSetWindowIcon（macOS guard 1.19 才加入），LWJGL 3.3.1 內建 GLFW 3.4 dev 回報 error 65548，此時 boot error callback（Window::bootCrash）仍生效 → TinyFD 對話框 + WindowInitFailed → 必炸。截圖對話框即 vanilla boot crash dialog，與驅動無關
- 修法：移除原生模式分支，1.13–1.18 預設 Java 一律 Rosetta x64 + LWJGL 3.2.3（GLFW 3.3.1 對 setIcon 靜默 no-op，MultiMC 標準解）；自訂 arm64 Java 路徑保留但啟動前 warn，崩潰後由 diagnose_graphics_crash 建議改「Follow Minecraft」
- 註解修正：mc_compat.rs header / LWJGL3_X64_OVERRIDE doc / 崩潰特徵表 / ADVICE 文字，影響範圍 1.13.x → 1.13–1.18
- 驗證：cargo check/clippy 乾淨，mc_compat 6 項 + classpath 替換測試通過；待實測 1.17.1 啟動
