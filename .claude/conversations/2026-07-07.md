# 2026-07-07

## World Save / Resource Pack / Shader Pack 路徑選取與生效

使用者要求：Create Instance 對話框的 World Save Path / Resource Pack Path / Shader Pack Path 三個欄位，除了讓使用者自訂路徑外，需要：
1. 空白時維持預設位置；有填寫時要真的生效（過去這三個欄位只存進 `InstanceConfig`，從未被任何地方讀取使用）。
2. 除了手動輸入/貼上路徑，還要加一個選取用的 icon，呼叫系統原生選擇框，並注意跨平台問題。

### 決策（brainstorming 澄清）
- 生效方式：啟動時動態帶入，不搬動檔案（symlink/junction），而非建立時複製或啟動時 UI 一次性複製。
- 三個欄位語意一致：都是「整個目錄取代」（World Save Path 取代整個 `saves`，非單一世界；Resource/Shader Pack 同理取代整個 `resourcepacks`/`shaderpacks`，非單一 pack 檔）。
- 這三欄位只在建立實例時可設定，沒有編輯 UI，因此正常情況下對應本機目錄永遠是全新或已正確連結，不會有「真實舊資料」需要保護的疑慮——但這個假設後來在 final review 被推翻（見下）。

### 實作（subagent-driven-development，5 個任務 + 1 次修正）
- Task 1：新增 Windows-only `junction` crate 依賴（NTFS junction，不需要 Developer Mode/管理員權限，優於 `symlink_dir`）
- Task 2：`instance_assets::sync_custom_dirs` — 純檔案系統連結邏輯，含 6 個 tempfile 單元測試
- Task 3：接進 `do_launch`（`src/view/launch.rs`）
- Task 4：Slint UI（`global.slint` 三個新 callback + `create-instance-dialog.slint` 資料夾圖示按鈕）
- Task 5：`src/view/create.rs` 用 `rfd::AsyncFileDialog::pick_folder()` 接上按鈕，沿用既有 `on_browse_java` 模式

### Final review 發現並修正兩個問題
1. **資料遺失風險**：`sync_one` 對「真實、非符號連結」的目錄一律 `remove_dir_all`，但既有的 instance-detail「新增檔案」功能會把使用者選的資源包/光影包直接複製進同一個 `resourcepacks`/`shaderpacks` 目錄——若使用者先加檔案再啟動，會被無聲刪除。修正為：真實目錄若非空就拒絕並報錯，只有空目錄才會被取代。
2. **fail-fast 沒做到**：`sync_custom_dirs` 原本放在下載完整個資源/函式庫之後才呼叫，壞路徑要下載完才會報錯。修正為移到 `do_launch` 最前面（`McPaths::new()` 之後），任何網路/下載動作之前。
