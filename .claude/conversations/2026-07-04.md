# 2026-07-04 對話記錄

## 使用者回報的四個問題

1. 遊戲開著時關閉 App，App 會卡住無法退出
2. 視窗放大後捲動實例列表仍然 lag
3. 離線狀態下離線帳號無法啟動遊戲
4. 捲軸（捲動）體驗需要優化

## 根因分析與修正

### 1. 關閉 App 卡死（src/view/instance_detail.rs）
- 根因：`spawn_log_reader` 用 `tokio::task::spawn_blocking` 阻塞讀取遊戲
  stdout/stderr；tokio runtime 在 main 結束 drop 時會**等待所有 blocking
  任務完成**，但 pipe 要等遊戲結束才 EOF → App 永遠卡住。
- 修正：改用 `std::thread::spawn`（獨立 OS thread，行程退出時直接回收，
  遊戲繼續執行不受影響）。

### 2. 離線無法啟動（launch.rs / mc_install.rs / mc_modloader.rs）
- 根因：`do_launch` 每次啟動都要連網——版本 JSON（Mojang manifest）、
  Java runtime manifest、asset index、Forge installer，任何一個失敗整個啟動失敗。
- 修正（local-first，順帶加快重複啟動）：
  - 版本 JSON：`load_or_fetch_version_detail`——本機 `versions/<id>/<id>.json`
    存在且可解析就直接用，否則連網取得後寫回快取。
  - Java（VersionDefault）：manifest 抓不到時，若本機 runtime 目錄已存在
    （含 Rosetta 後綴目錄）直接沿用。
  - Asset index：`indexes/<id>.json` 本機存在就不重抓。
  - Forge：新版（1.13+）profile id 可預先推導，已安裝就不下載 installer
    （舊版 Forge id 藏在 installer 內，離線仍需先安裝過走 early-return 前那步，
    此情境暫不支援）。
  - 檔案本體（client jar / libraries / assets objects）原本就有
    size-match 跳過機制，離線時不會發請求。
- 限制：**首次**啟動某版本仍需網路；離線帳號 + 已完整啟動過的實例可離線重啟。

### 3+4. 捲動 lag / 捲軸優化
- `Cargo.toml`：啟用 `[profile.dev.package."*"] opt-level = 3`（Slint 渲染器
  在依賴中，debug 跑 opt-level 0 是 lag 大宗；只影響首次編譯時間）。
- `instances.slint`：虛擬列表視窗改為量化的整數列索引（`first-live-row` /
  `last-live-row` 掛在 ScrollView 上），卡片的 in-viewport 由像素比較改為
  整數比較，卡片內容的建立/銷毀只在跨列邊界發生。
- 尚未做（候選）：release/skia renderer 評估、hover 動畫在捲動時的重繪成本。

## 驗證
- `cargo check` / `cargo clippy` 乾淨。
- 單元測試：spawn_log_reader ×2、launch helpers ×5、mc_install/mc_modloader
  全部通過；新增 `test_install_forge_skips_when_profile_exists`。
- 待人工驗證：遊戲開著時關 App 應立即退出且遊戲不中斷；斷網重啟已裝實例；
  視窗最大化捲動流暢度（記得先讓 dev 依賴以 opt-level 3 重新編譯一次）。
