# 對話記錄 2026-06-08

## 本次重點：Skin Management 頁面實作

### 實作功能
在 Account 頁面的「Manage Appearance」按鈕觸發一個全螢幕 overlay 對話框，讓用戶管理 Minecraft 皮膚。

### 修改的檔案

| 檔案 | 修改內容 |
|------|---------|
| `Cargo.toml` | 加入 `rfd = "0.14"`；reqwest 新增 `multipart` feature |
| `ui/global.slint` | 新增 `AppearanceLogic` 全局 singleton |
| `ui/components/pages/appearance.slint` | **新建**：皮膚管理 overlay 對話框 |
| `ui/components/index.slint` | 匯出 `AppearanceDialog` |
| `ui/main.slint` | import/export `AppearanceLogic`，加入 overlay |
| `src/mc_api.rs` | 新增 `upload_skin_from_url()` + `upload_skin_from_file()` |
| `src/view.rs` | 連接 5 個 AppearanceLogic callbacks |

### 架構決策
- **Overlay 模式**（同 CreateInstanceDialog 而非新 sidebar tab），因為 manage-appearance 是從 account 頁面觸發的。
- `rfd::FileDialog`（blocking API）直接在 Slint main thread 呼叫，阻塞時系統 modal dialog 已接管 UI，不影響體驗。
- 皮膚上傳走 tokio::spawn 避免阻塞 event loop。
- 上傳中（is_uploading=true）時所有輸入和按鈕自動 disabled。

### API 規格
- URL 上傳：`POST /minecraft/profile/skins` → `application/json` `{ variant, url }`
- 本機檔案：`POST /minecraft/profile/skins` → `multipart/form-data` fields: `variant` + `file`
- Token 從 `GLOBAL_CACHE["mc_ac_key"]` 取得

### Cargo Check 結果（2026-06-08 本次對話補充）

**問題**：`cargo check` 出現 2 個 borrow/move 錯誤：
- `E0505`：`ui` 在 `ui.global::<PageAccountLogic>()` 被借用的同時，`on_manage_appearance(move || {...})` 試圖 move 捕獲 `ui`
- `E0382`：`ui` 被 move 進閉包後，下方 `ui.run()` 無法再使用

**修正**（`src/view.rs`）：
1. 在 `on_manage_appearance` 呼叫前新增 `let main_ui_weak_for_appearance = ui.as_weak();`
2. 閉包內的 `let main_ui_weak_inner = ui.as_weak();` 改為 `let main_ui_weak_inner = main_ui_weak_for_appearance.clone();`

**結果**：`cargo check` 通過，無 warning/error。
