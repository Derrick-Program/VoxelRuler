## 啟動即自動最小化主視窗

使用者要求：只要實例啟動後就自動觸發隱藏（最小化）主視窗，不需要使用者自己點關閉按鈕。

### 決策（brainstorming 澄清）
- 觸發點：`do_launch` 回傳 `Ok(child)`（遊戲行程成功 spawn）的當下，而非下載/安裝階段。
- 遊戲結束後（正常或異常）刻意不自動還原視窗，維持最小化，使用者自行從 Dock/工作列點回來。
- 不新增設定/開關，與既有「執行中點關閉→改最小化」功能一樣是寫死行為（該功能也沒有開關）。
- 明確不動：`on_close_requested`（既有「執行中點關閉改最小化」）、`pending_quit` 異常退出時的還原邏輯——兩者互不干涉。

### 實作（subagent-driven-development，1 個任務）
- 在 `src/view/launch.rs` 的 `on_launch_instance` 成功分支、緊接在既有 `set_instance_status(&ui_weak, &instance_id, "running")` 之後，新增一段透過 `slint::invoke_from_event_loop` + `ui_weak.upgrade()` 呼叫 `ui.window().set_minimized(true)`，沿用檔案裡既有還原呼叫的同一套模式。
- 任務審查與 whole-branch review（opus）都確認：event loop 上兩個 closure 依序觸發但互不干擾（各自動的是不同狀態）、同時有多個實例執行時重複呼叫是無害的 no-op、與 `pending_quit`/`on_close_requested` 完全正交，無需修正。

- Plan: `docs/superpowers/plans/2026-07-07-auto-minimize-on-launch.md`

- `just fmt` / `just lint` / `just test`（165 passed）全過

## 實例詳情頁 Version 分頁可切換 Mod Loader

使用者要求：`src/view/instance_detail.rs` 的 Version 分頁要能改 Mod Loader（Forge 等），按 Save 後一併存檔。

### 決策（brainstorming 澄清）
- Save 行為：版本 + Mod Loader + Loader 版本合併成單一「Save」按鈕一起存檔，比照 Create Instance 對話框的送出方式（而非版本、Mod Loader 各自獨立存檔）。
- UI 樣式：直接沿用 Create Instance 對話框既有的 None/Fabric/Forge/NeoForge 圓形選項 + Loader 版本下拉樣式，不另外設計新樣式。
- Create 對話框裡原本的 loader 版本抓取邏輯（debounce + 世代計數器防競態 + availability 檢查）抽出共用 helper（`ModLoaderApi::fetch_loader_state`），debounce/預設值選擇邏輯留在各自呼叫端。

### 實作（subagent-driven-development，8 個 commit）
1. `feat(instance): add ModLoaderApi::fetch_loader_state helper`（`src/mc_modloader.rs`）
2. `refactor(instance): reuse fetch_loader_state in create dialog loader logic`（`src/view/create.rs`，行為不變的重構）
3. `refactor(instance): extract validate_version_and_loader for reuse`
4. `feat(ui): add mod loader edit state to InstanceDetailLogic`（`ui/global.slint`，純新增）
5. `feat(instance): fetch mod loader versions in instance detail dialog`（`refresh_loader_state` + 開啟對話框時的初始化）
6. `fix(instance): bump loader fetch generation before early return`（task review 抓到的競態排序 bug：世代計數器要在 `mc_version` 為空的提早 return 之前就遞增，否則舊的 fetch 結果可能蓋掉剛重設的 UI 狀態）
7. `feat(instance): persist mod loader and loader version on Save`（`save-version` → `save`，一次存 3 個欄位，驗證共用 `validate_version_and_loader`）
8. `feat(ui): add mod loader picker to instance detail Version tab`（實際 UI 元件）

每個任務都有獨立 task reviewer 審查（spec compliance + code quality），第 5 個任務的競態 bug 是審查抓到後修的。全分支 review（opus）：Ready to merge - Yes，僅 2 個 Minor 建議（開啟對話框時的初始 fetch 也套用了 100ms debounce、preferred-vs-default 版本選擇邏輯沒有獨立單元測試），無 Critical/Important。
