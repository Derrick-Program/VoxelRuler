## 主題
修復「部分版本啟動時 lib 缺失」問題

## 根因分析

1. **舊版 natives（≤約 1.18）從未下載、從未解壓**
   - 舊版格式的原生函式庫放在 `downloads.classifiers`（如 `natives-osx`），並由 `natives` 欄位（OS → key，含 `${arch}`）指定
   - `McLibrary` 結構缺 `natives` / `extract` 欄位；`install_libraries()` 只下載 `artifact`
   - 結果：`natives_dir` 永遠是空的 → `UnsatisfiedLinkError: no lwjgl in java.library.path`
2. **macOS jna hack 兩端不一致**
   - classpath 端把 jna 路徑 `5.10.0` 字串替換成 `5.13.0`，但 install 端從未下載 5.13.0 的 jar → classpath 指向不存在的檔案
   - 舊的 jna-platform 注入：size 寫錯（1345511，實際 1363209，導致每次啟動重新下載）、且注入的 jar 從未進 classpath（等於無效）
3. **classifier-only lib 誤上 classpath**
   - 無 `artifact` 只有 `classifiers` 的 lib（如 macOS 的 lwjgl-platform 2.9.2）經 maven fallback 被放上 classpath，指向永遠不會下載的 jar
4. **spawn 前無缺檔檢查**，缺 jar 只看得到 Java 端難懂錯誤

## 修改內容

- `mc_types.rs`：`McLibrary` 新增 `natives`、`extract` 欄位；新增 `McExtract`
- `mc_parser.rs`：
  - 新增 `native_classifier_key()`（含 `${arch}` 替換與 classifiers fallback）
  - 新增 `jna_needs_bump()` / `jna_compat_rel_path()`（jna 5.x < 5.13 → 5.13.0，3.x/4.x 不動）
  - `build_classpath` 重構為 `classpath_paths()`；classifier-only lib 不再上 classpath
  - 新增 `missing_classpath_files()` 啟動前檢查
- `mc_install.rs`：
  - `install_libraries()` 同時下載 OS 對應的 natives classifier jar
  - macOS jna 修正：與 classpath 一致地下載 jna / jna-platform 5.13.0（正確 size/sha1，取自 Mojang 1.20.2 官方資料）
  - 新增 `extract_natives()`：解壓 natives jar 至 natives_dir（尊重 `extract.exclude`、防 zip-slip、已存在同大小跳過以避開 Windows 檔案鎖）
- `view.rs`：`do_launch()` 在 install_libraries 後呼叫 `extract_natives`；spawn 前做 classpath 缺檔檢查並回報明確錯誤
- `Cargo.toml`：新增 `zip = { version = "2", default-features = false, features = ["deflate"] }`
- 新增測試：jna bump 判斷、natives key 解析（含 1.12.2 / 1.21 資料驗證）、natives 解壓 roundtrip（exclude / META-INF 過濾）

**UI**

- `view.rs`：啟動時抓 Mojang java-all 清單填兩個下拉（哨兵值 "Follow Global Settings" / "Follow Minecraft (Auto)" ↔ 空字串）；instance 卡片設定鈕開編輯對話框；儲存寫 instance.toml（watcher 自動同步列表）

## 第三部分：Java 設定改為三模式下拉（derrick 修正需求）

原本的設計（列出所有 Mojang runtime component 供選擇）不對。正確需求：
- **Instance 下拉三選項**：Use Global Settings / Use Minecraft Runtime / Use Custom Java
- **全域 Settings 下拉兩選項**：Use Minecraft Runtime / Use Custom Java
- 選「Use Custom Java」才顯示路徑輸入框；不開放選 Mojang component

### 變更
- `InstanceConfig.java_runtime` → `java_mode`（"global"/"minecraft"/"custom"，空字串 = global）
- `AppSettings.java_runtime` → `java_mode`（"minecraft"/"custom"，空字串 = minecraft）
- view.rs：`JavaSource` 移除 Runtime variant；`resolve_java_source` 改模式判斷；
  移除 java-all API 抓取（不再需要），模式清單改為啟動時同步設定；
  儲存驗證：custom 模式必填路徑且檔案需存在
- slint：兩邊 ComboBox 綁 `java-mode-list`/`selected-java-mode`，路徑欄位條件顯示
- 修正前次編譯錯誤：`McAction` 為 typestate 泛型，helper 簽名補 `<Unauthenticated>`

### 啟動解析（最終版）
instance.java_mode: custom→自訂路徑 / minecraft→版本預設 / global→看全域
全域.java_mode: custom→自訂路徑 / 其他→版本預設（javaVersion.component，無則 jre-legacy）

## 第四部分：自訂 Java 選擇體驗（掃描 + 檔案選擇框）

### 需求
選「Use Custom Java」後：下方直接列出掃描到的常見 Java 安裝路徑（點選即用），
最底下提供「Browse...」開啟系統原生檔案選擇框。

### 實作
- 新增 `src/java_scan.rs`：`scan_system_javas()` 掃描三平台常見位置
  - macOS：`/Library/Java/JavaVirtualMachines`、`~/Library/...`、Homebrew（/opt/homebrew、/usr/local）
  - Linux：`/usr/lib/jvm`、`/usr/java`、`/opt/jdk*`、`/usr/bin/java`
  - Windows：Program Files 下 Java / Adoptium / Microsoft / Corretto / Zulu / BellSoft
  - 通用：`JAVA_HOME`、sdkman、asdf、JetBrains `~/.jdks`；結果去重排序
- 啟動時 `spawn_blocking` 背景掃描，完成後填入兩處 `detected-java-list`
- 新增 `rfd = "0.15"` 依賴：`browse-java()` callback 開原生檔案選擇框（slint callback 在主執行緒，符合 macOS NSOpenPanel 要求）
- UI：自訂模式顯示 120px ScrollView 清單（點選 = 設 java-path、綠色高亮目前選擇）、
  底部 Browse 按鈕 + 目前選擇路徑顯示；編輯對話框高度自訂模式時 480→620px
- 移除手動輸入框（路徑只能從清單或檔案選擇框來，儲存時仍驗證檔案存在）

### 注意
- **Linux 編譯 rfd 需要 GTK3 開發套件**（`libgtk-3-dev`）；之後 M6 CI 要記得裝
- [ ] 本機 `cargo check` / `cargo test` 驗證

### 修正：Linux 打包為 AppImage（derrick 提出）
- rfd 改用 `xdg-portal` 後端（`default-features = false, features = ["xdg-portal", "tokio"]`）
  - Linux 不連結 GTK → CI 不需 libgtk-3-dev、AppImage 無需煩惱 GTK 打包
  - 對話框走 D-Bus 的 xdg-desktop-portal（GNOME/KDE 等現代桌面內建）
  - macOS / Windows 不受影響，仍走原生對話框
- xdg-portal 只有 async API → browse 改用 `rfd::AsyncFileDialog` + `slint::spawn_local`
- 已知限制：極簡 WM 且未裝 xdg-desktop-portal 的環境會開不出對話框（仍可點選掃描清單）
